# HeadsetConnector

Мессенджер-мост между владельцами **Pico** и **Meta Quest**. Один аккаунт, один список друзей, одни чаты — независимо от того, какой шлем на голове.

Состоит из двух частей:

| Часть | Где | Что делает |
|---|---|---|
| `app/` | шлем Pico / Quest, телефон | Клиент: вход, друзья, чаты, комнаты, голосовые |
| `server/` | ПК или хостинг | Аккаунты, друзья, сообщения, медиа |

И Pico, и Quest работают на Android, поэтому один и тот же APK ставится на оба шлема.

## Что уже работает

- Регистрация и вход по юзернейму и паролю (пароли — scrypt, токены — случайные, в базе только хеши).
- Профиль: отображаемое имя и аватарка.
- Поиск людей по юзернейму, заявки в друзья, принятие/отклонение, удаление.
- Личные чаты — только с друзьями, без спама.
- Комнаты: публичные (видны всем) и закрытые (вход по 6-значному коду).
- Текст и **голосовые сообщения** (AAC, до 2 минут) с прослушиванием прямо в чате.
- Автообновление: список чатов и сообщения подтягиваются каждые 2–4 секунды.
- Поиск сервера в локальной Wi-Fi сети прямо из приложения.

## Чего пока нет

- Живой голосовой связи (WebRTC) — это следующий этап, сейчас голос только записями.
- Push-уведомлений — приложение обновляет чат, пока оно открыто.
- Сквозного шифрования — сообщения хранятся на вашем сервере в открытом виде.
- Модерации и лимитов — сервер рассчитан на друзей, а не на публичный сервис.

## Готовый сервер

Сервер уже развёрнут на бесплатном alwaysdata и работает круглосуточно:

| Что | Адрес |
|---|---|
| Для приложения | `https://headsetconnector.alwaysdata.net` |
| Панель управления | `https://headsetconnector.alwaysdata.net/admin` |

Адрес вшит в APK, поэтому при первом запуске его вводить не нужно. Пароль
панели хранится в `~/hc/.env` на сервере (меняется там же + Restart сайта).

## Быстрый старт (локально)

1. Запустить сервер:

   ```powershell
   cd server
   .\start.ps1
   ```

   Он напечатает адрес вида `http://192.168.1.10:8787`.

2. Разрешить входящие подключения в брандмауэре Windows (один раз), иначе шлем
   не увидит сервер:

   ```powershell
   New-NetFirewallRule -DisplayName "HeadsetConnector 8787" -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow
   ```

3. Установить `HeadsetConnector-0.3.apk` на шлем (и на телефон, если удобно).

4. В приложении: создать аккаунт (сервер уже указан) либо нажать «изменить» и
   ввести адрес своего сервера. На втором устройстве — второй аккаунт, добавить
   друг друга по юзернейму.

## Панель управления

Открывается в браузере с любого устройства:

```
http://<адрес-сервера>:8787/admin
```

Пароль администратора задаётся переменной `ADMIN_PASSWORD` на сервере. Если её
не задать, сервер сгенерирует пароль при первом запуске и напечатает его в лог
(на VPS: `journalctl -u headsetconnector | head`).

Что умеет панель:

- статистика: пользователи, активные сессии, сообщения, комнаты, объём медиа;
- поиск по юзернейму и имени;
- блокировка и разблокировка (все сессии пользователя сразу завершаются);
- сброс пароля с выдачей временного;
- удаление пользователя вместе с его сообщениями и друзьями;
- список комнат и удаление любой комнаты.

На ПК для этого ничего запускать не нужно — это обычный сайт на сервере.

## Доступ из любой точки мира

Друзьям не нужно ничего, кроме APK: сервер живёт по постоянному адресу в
интернете. Сейчас он на бесплатном **alwaysdata** (1 ГБ диска, HTTPS, Node.js 24).

Обновить сервер или развернуть заново:

1. Регистрация (если аккаунта ещё нет): <https://www.alwaysdata.com/en/register/?p=2012>
2. `cd server\alwaysdata` → `.\deploy-alwaysdata.ps1 -Account ЛОГИН`
3. Один раз создать сайт в панели alwaysdata (тип `Node.js`, команда
   `node /home/ЛОГИН/hc/server.js`).

Адрес вида `https://ЛОГИН.alwaysdata.net`. Подробно:
[`server/alwaysdata/README.md`](server/alwaysdata/README.md).

APK собирается с адресом внутри — тогда пользователю остаётся только войти:

```powershell
.\gradlew.bat :app:assembleDebug "-Phc.server=https://ЛОГИН.alwaysdata.net"
```

Альтернативы: Oracle Cloud Always Free (нужна карта, зато 200 ГБ и свой IP),
любой VPS за 2–4 $ ([`server/DEPLOY.md`](server/DEPLOY.md)), либо сервер на
старом Android-телефоне в Termux ([`server/termux/README.md`](server/termux/README.md)).

Для быстрой пробы без хостинга есть туннель:

```powershell
cd server
.\tunnel.ps1
```

Он выдаёт временный `https://…trycloudflare.com`, но адрес меняется при каждом
запуске, и ПК должен быть включён.

## Как устроено

```
app/                    Android-клиент (Kotlin, Jetpack Compose)
├── data/               HTTP-клиент, модели, настройки
├── net/                поиск сервера в подсети
├── audio/              запись и воспроизведение голосовых
├── vm/                 состояние приложения
└── ui/                 экраны: вход, чаты, чат, друзья, профиль

server/
├── server.js           HTTP API + SQLite + медиа
├── admin.html          веб-панель управления
├── test-api.js         27 проверок API
├── test-admin.js       23 проверки панели
├── alwaysdata/         бесплатный публичный хостинг
├── termux/             сервер на старом Android-телефоне
├── Dockerfile
├── start.ps1           локальный запуск
└── tunnel.ps1          временный публичный туннель
```

Сервер не использует npm-зависимости: только встроенные модули Node 22+
(`node:sqlite`, `node:http`, `node:crypto`). База и медиа лежат в `server/data`.

## Сборка клиента

```powershell
$env:JAVA_HOME="$env:USERPROFILE\.jdks\jbr-21.0.11"
.\gradlew.bat :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Gradle 8.7, AGP 8.5.2, Kotlin 2.0.21, Compose BOM 2024.09.03, minSdk 26.

## План

1. Отправка файлов и картинок в чат.
2. Push-уведомления через WebSocket вместо опроса.
3. Живые голосовые комнаты (WebRTC + TURN).
4. Постоянный хостинг и нормальный домен.
5. VR-режим: панель с чатом внутри VR-приложения, а не плоское окно Android.

## Безопасность

- Пароли хранятся как scrypt-хеши с солью, токены — случайные 32 байта.
- Сервер не отправляет данные наружу: всё в вашей базе.
- Закрытая комната защищена кодом, но не шифрованием — не делитесь личным.
- Для публичного сервера обязательно нужен HTTPS (туннель или reverse-proxy).
